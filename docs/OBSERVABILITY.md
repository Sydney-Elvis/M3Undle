# Observability

M3Undle exposes health probes, Prometheus-compatible metrics, and authenticated JSON diagnostics for operators.

Use this page when wiring M3Undle into Prometheus, Grafana Cloud, Grafana Alloy/Agent, Uptime Kuma, Docker health checks, or a reverse proxy.

---

## Endpoints

| Endpoint | Auth | Purpose |
|---|---|---|
| `GET /metrics` | Metrics mode | Prometheus/OpenMetrics scrape output. The path is configurable. |
| `GET /livez` | Anonymous | Liveness probe. Returns healthy when the process can answer requests. |
| `GET /readyz` | Anonymous | Readiness probe. Checks whether M3Undle is ready to serve normal traffic. |
| `GET /healthz` | Anonymous | JSON health summary. |
| `GET /health/ready` | Anonymous | Compatibility alias for readiness. |
| `GET /api/admin/diagnostics/providers` | UI admin | Provider fetch and channel diagnostics. |
| `GET /api/admin/diagnostics/streams` | UI admin | Active and recently ended stream sessions, clients, and upstreams. |
| `GET /api/admin/diagnostics/lineup` | UI admin | Published lineup status and recent snapshots. |
| `GET /api/admin/diagnostics/epg` | UI admin | EPG source, fetch, and mapping diagnostics. |

Metrics are for scrape systems. Diagnostics APIs are for humans and automation that already have admin/API access.

---

## Metrics Access Modes

Metrics access is configured under **Settings -> Observability** or with startup configuration.

| Mode | Behavior |
|---|---|
| `Disabled` | `/metrics` returns `404`. |
| `LocalOnly` | Default. Allows loopback plus configured CIDR ranges only. Private LAN ranges are not allowed automatically. |
| `Token` | Requires a metrics token via `Authorization: Bearer <token>` or `?token=<token>`. |
| `Public` | No metrics authentication. Use only behind trusted network controls. |

Metrics requests are rate-limited per caller. Excessive scrapes return `429`.

### Tokens

Metrics tokens are generated by M3Undle and shown once when created. Only a hash is stored.

Token metadata remains visible in the UI:

- name
- scope, currently `metrics:read`
- created time
- last used time
- expiration
- expired state

Deleting a token immediately prevents further scrapes with that token. Regeneration is create-new plus delete-old.

## Configuration

The default settings are:

```yaml
M3Undle:
  Observability:
    Metrics:
      Enabled: true
      Path: "/metrics"
      Mode: "LocalOnly"
      EnableChannelLabels: false
      LocalAllowedCidrs: []
```

Environment variable form for Docker:

```yaml
environment:
  M3Undle__Observability__Metrics__Enabled: "true"
  M3Undle__Observability__Metrics__Path: "/metrics"
  M3Undle__Observability__Metrics__Mode: "LocalOnly"
  M3Undle__Observability__Metrics__EnableChannelLabels: "false"
  M3Undle__Observability__Metrics__LocalAllowedCidrs__0: "192.168.1.0/24"
```

`EnableChannelLabels` is defaulted off to protect Prometheus cardinality. Current built-in metrics do not emit raw URLs, usernames, tokens, IP addresses, or channel names.

## Prometheus Examples

Local-only scrape from the same host or container network:

```yaml
scrape_configs:
  - job_name: m3undle
    scrape_interval: 30s
    static_configs:
      - targets: ["m3undle:8080"]
```

Token-protected scrape:

```yaml
scrape_configs:
  - job_name: m3undle
    scrape_interval: 30s
    metrics_path: /metrics
    authorization:
      type: Bearer
      credentials: "paste-the-token-here"
    static_configs:
      - targets: ["m3undle:8080"]
```

For Grafana Cloud, configure Grafana Alloy or Grafana Agent to scrape `http://<host>:8080/metrics` and remote-write the result to your Grafana Cloud Prometheus endpoint.

## Metric Labels

M3Undle keeps labels intentionally small.

| Label | Used by | Notes |
|---|---|---|
| `provider_id` | Provider and stream metrics | Stable provider identifier. |
| `profile_id` | Lineup metrics | Stable profile identifier. |
| `stream_type` | Stream session counters | For example `live`, `vod`, or `series` where known. |
| `protocol` | Stream session counters | Derived protocol where known. |
| `result` | Failure counters | Bounded result value. |
| `route` | HTTP metrics | Route pattern, not raw URL. |
| `method` | HTTP metrics | HTTP method. |
| `status_code` | HTTP metrics | Numeric status code string. |
| `version` | `m3undle_build_info` | Build version. |
| `build_number` | `m3undle_build_info` | Build number or `unknown`. |

Do not add dashboard queries that expect labels for raw stream URLs, users, tokens, client IPs, or channel names. Those values are deliberately excluded.

## Health Probes

Use `/livez` for restart decisions and `/readyz` for traffic-routing decisions.

```bash
curl -i http://<host>:8080/livez
curl -i http://<host>:8080/readyz
curl -s http://<host>:8080/healthz
```

`/readyz` is stricter than `/livez`. It can report not-ready while the process is still alive, such as during startup or when required runtime dependencies are unavailable.

Docker Compose example:

```yaml
services:
  m3undle:
    healthcheck:
      test: ["CMD", "wget", "-q", "-O", "-", "http://localhost:8080/readyz"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 30s
```

## Diagnostics APIs

Diagnostics APIs require existing admin/UI authorization. They are not exposed through metrics-token authentication.

```bash
curl -s http://<host>:8080/api/admin/diagnostics/providers
curl -s http://<host>:8080/api/admin/diagnostics/streams
curl -s http://<host>:8080/api/admin/diagnostics/lineup
curl -s http://<host>:8080/api/admin/diagnostics/epg
```

Use these APIs when investigating provider fetches, stream sharing, lineup publish history, or EPG source behavior. Use `/metrics` for time-series monitoring.

## Troubleshooting

| Symptom | Meaning | Check |
|---|---|---|
| `/metrics` returns `404` | Metrics are disabled or mode is `Disabled`. | Check Settings -> Observability. |
| `/metrics` returns `401` | Token mode is enabled and no valid token was supplied. | Use `Authorization: Bearer <token>`. |
| `/metrics` returns `403` | Local-only mode rejected the caller address. | Add an explicit CIDR or scrape from loopback. |
| `/metrics` returns `429` | Scrape rate limit exceeded. | Increase scrape interval; avoid parallel scrapes. |
| `/readyz` is unhealthy but `/livez` is healthy | Process is alive but not ready for normal traffic. | Check database, refresh state, and active lineup status. |
| Metrics are missing expected labels | Labels are intentionally limited. | Confirm queries use documented labels only. |

Useful checks:

```bash
curl -i http://<host>:8080/metrics
curl -i http://<host>:8080/livez
curl -i http://<host>:8080/readyz
curl -s http://<host>:8080/healthz
docker logs m3undle --tail 200
```

## Implementation Notes

M3Undle instruments application metrics with `.NET System.Diagnostics.Metrics` and exposes scrape output through the ASP.NET Core OpenTelemetry Prometheus exporter. Health endpoints use ASP.NET Core health checks.
